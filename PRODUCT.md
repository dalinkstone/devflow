# Product

## Register

product

## Users

Developers running Claude Code or Codex in Daytona sandboxes. They use devflow
from a terminal while starting work, checking progress, reconnecting, and
managing one or more agents.

## Product Purpose

Devflow makes cloud agent sessions feel as direct as local terminal work. A
successful interface keeps the current state obvious, makes the next action
clear, and stays out of the way.

## Brand Personality

Calm, direct, capable. Copy is brief, concrete, and friendly without narration
or hype.

## Anti-references

Raw infrastructure logs presented as product UI, dashboard-like terminal
chrome, decorative TUI elements, noisy status repetition, and output that
depends on color to be understood.

## Design Principles

1. Show the answer first.
2. Preserve useful detail without exposing incidental noise.
3. Use one consistent vocabulary for state, progress, and next actions.
4. Keep commands composable and predictable in both terminals and scripts.
5. Add interface weight only when it reduces cognitive load.

## Accessibility & Inclusion

All output remains understandable without color and when redirected. Respect
`NO_COLOR`, avoid animation, preserve readable contrast, and never use symbols
as the only state signal.
